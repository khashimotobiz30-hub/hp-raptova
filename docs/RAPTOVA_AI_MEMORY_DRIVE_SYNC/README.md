## 保存場所・同期・Gitの扱い（RAPTOVA_AI_MEMORY）

- **正本の置き場所**: このフォルダ **RAPTOVA_AI_MEMORY** は **Google Drive 上で管理するナレッジ用フォルダ**として扱う（Cursor / エディタで開いていても、運用上の完了は **Drive 側の保存・同期**を基準にする）。
- **通常の更新フロー**: 対象の `.md` を **編集して保存**し、**Google Drive に同期されていれば完了**とする。
- **HP本体リポジトリとの関係**: **RAPTOVA公式サイトなどのコード**は **別リポジトリ**で管理する。**この MEMORY フォルダの更新**と **HP のコード変更**は切り離して考える。
- **Git（add / commit / push）**: **RAPTOVA_AI_MEMORY の更新だけ**であれば、**原則として Git 操作は不要**（Drive が正）。混同しやすいので、**「MEMORY を直したから push」はしない**のがデフォルト。
- **Git が必要になるのは**: **HP本体のコード**や **別アプリのリポジトリ**など、**該当プロジェクトのリポジトリ内のファイルを変更したとき**だけ。その場合は **そのリポジトリで** `git add` / `commit` / `push` を行う。
- **将来 Git で MEMORY を管理する場合**: 運用を変えるなら **その時点で** `README.md` に **別ルール**（ブランチ方針、push のタイミング、Drive との関係）を明記する。現時点では **未採用**。

※ドキュメントの**書き方**（追記優先、`decision_log.md` など）は、下記「情報を追加・更新する時のルール」を参照。

## 情報を追加・更新する時のルール

1. **既存ファイルへの追記を優先する**。新規ファイルは安易に増やさない。
2. 「普段参照層」は要点のみ。長文は「詳細参照層」に置く。
3. 方針が変わったら `decision_log.md` に理由とともに記録してから、関連ファイルを更新する。
4. プレースホルダー（`（追記）`）が埋まったら削除していい。

## decision_log.md の使い方

「なぜその判断をしたか」を残すためのファイル。同じ議論を繰り返さないための記録。

- **書くタイミング**: 方針を変えた時・新しいファイルを作った時・迷って決断した時
- **書く内容**: 決めたこと・理由・次にやること
- **迷った時**: まずここに「迷っていること」を書いてから整理する。答えが出たら更新する。

---

## ファイルを増やしすぎないために

- 新しいトピックが出たら、まず既存ファイルの「未確定メモ」に書く
- 情報量が増えて独立ファイルが必要になってから分割する
- 「管理するための管理」にならないよう、実際に参照するファイルだけ維持する

## 終了時の定型依頼文

作業や相談が一区切りついたら、AIに以下をそのまま投げる。

```
今回決まった内容を、RAPTOVA_AI_MEMORY のどのファイルに追記・更新すべきか判断して、追記案を作ってください。

その際、
- 過去方針から変更がある場合は、decision_log.md に「以前の方針・変更内容・変更理由・最新方針」を残す
- 普段参照ファイルは、AIが迷わないように最新方針へ更新する
- 詳細参照ファイルは、必要がある場合のみ補足・更新履歴として追記する
- 新規ファイルは必要になった時だけ提案する
という前提で整理してください。
```
