#### 1. 公式HPの制作目的

RAPTOVA公式HPは、単なる名刺サイトではなく、**営業・信用獲得・実績蓄積・ブランドの原点確認**を兼ねた**事業拠点**として制作する。

主な目的は、今後これまでの人脈や紹介先に営業をかける際に、橋本自身が**何を事業として行い、何を支援でき、どの程度の品質で形にできるのか**を証明すること。

口頭説明だけでは伝わりにくい**「企画・構成・文章・デザイン・実装まで形にできる力」**を、公式HPそのものと **Projects に載せる実績・事例**（補助語として **Works**＝制作実績・ケーススタディ）を通じて示し、「このクオリティで提供できるなら任せたい」と思ってもらうための**信用材料**にする。

また、QUESTORIAをはじめとした制作物を一過性の成果物で終わらせず、**実績として蓄積**し、RAPTOVAの提供価値を伝える**ポートフォリオ基盤**としても機能させる。

同時に、RAPTOVAがどういう思いで作られ、どのような事業を行い、何を大切にするのかを**自分自身が立ち返れる場所**としても位置づける。

**優先順位**:

1. 営業時の信用獲得  
2. できること・事業内容の説明  
3. 実績を蓄積するポートフォリオ  
4. RAPTOVAの思想に立ち返るブランド拠点  

**位置づけ**: 「**信用獲得を目的とした、営業・実績・ブランド拠点型の公式サイト**」とする。

#### 2. 想定閲覧者

主な想定閲覧者は、**既存人脈・紹介先・営業先・パートナー候補**とする。

特に**初期フェーズ**では、次の2者を**最優先ターゲット**とする。

1. **既存人脈・過去のつながり** — 前職関係者、知人、紹介者、過去の仕事関係者など、橋本をある程度知っている人。  
2. **案件紹介・協業のパートナー候補** — 採用コンサル・人材系・制作会社・営業パートナーなど、紹介や協業の可能性がある相手。

現時点では、**不特定多数の検索流入を主目的**にはしない。営業・紹介・SNS・名刺代わりの URL 共有から訪問した人に対して、**何の事業か・何を支援できるか・どの品質か**を伝え、**信用と相談理由**を作るサイトとして設計する。

- **既存人脈**には、橋本個人への信頼を **RAPTOVAという事業への信頼**に変換することを重視する。  
- **パートナー候補**には、紹介できるか・組めるか・クライアントに紹介しても問題ない品質かを**判断できる材料**を提示する。

**閲覧者の優先順位**:

1. 既存人脈・過去のつながり  
2. 案件紹介・協業のパートナー候補  
3. 営業先・見込み顧客  
4. SNS・検索経由の初見ユーザー  

#### 3. サイト閲覧後に起こしたい行動

目的は単なる閲覧ではなく、閲覧後に「**一度話を聞いてみたい**」「**この人に相談できそう**」「**案件を紹介しても大丈夫そう**」と感じてもらうことにある。

初期フェーズでは、**いきなり発注や問い合わせ**よりも、**会話のきっかけ**を優先する。

**行動の優先順位**:

1. 一度話を聞いてみたいと思ってもらう  
2. 相談できる案件のイメージを持ってもらう  
3. 案件紹介・協業の候補として認識してもらう  
4. 問い合わせ・相談につなげる  
5. 今すぐ案件がなくても、今後相談したい人として記憶してもらう  

**CONTACT** は「今すぐ発注する」より、「**まずは相談する**」「**プロジェクトを相談する**」「**協業について話す**」といった、**相談・紹介・協業の入口**として設計する。信用・理解・相談イメージ・紹介しやすさを作ったうえで、問い合わせや会話につなげる。

#### 4. RAPTOVAの見せ方・ポジショニング

RAPTOVAは、単なる Web 制作会社や AI ツール代行ではなく、採用・営業・事業推進に必要な情報発信や制作物を、**企画・構成・文章・デザイン・実装まで一気通貫**で形にする**「AI時代の企画・制作パートナー」**として見せる。

大手採用支援会社での営業経験を背景に、**採用・人材領域の現場感や企業側の課題感**を理解したうえで、AI を活用したスピードと柔軟性を掛け合わせ、Webサイト、採用LP、サービス資料、営業資料、原稿、業務支援ツールなどを制作する。

HP上では、「Webが作れる」「資料が作れる」「AIが使える」を単独で訴求するのではなく、**採用・営業・事業推進に必要な“伝えるもの”を作る**という軸で整理する（**採用を前面に固定しない**ことと**採用文脈の現場理解は強み**は両立する）。

**強み**:

1. 採用・人材領域の現場理解  
2. 企画・構成・言語化の力  
3. AIを活用した制作スピードと柔軟性  
4. Web・資料・文章まで横断して形にできる実装力  

**HP上で目指す印象**:

- ただ作るだけではなく、考えるところから入ってくれそう  
- 採用や事業の文脈を理解してくれそう  
- AIを使って早く柔軟に形にできそう  
- Webも資料も文章もまとめて相談できそう  
- 小規模だが、企画力と制作品質がある  
- 相談しやすいが、安売り感はない

### サイト全体の情報フロー（設計思想）

サイト全体の情報設計は、次の流れで整理する（**細かい文言・料金・FAQ ではなく、長期に固定する設計思想**）。

```txt
思想
↓
現在の支援領域
↓
実行・検証・実装
```

- **思想**: ブランド・MVV・姿勢・なぜ RAPTOVA か。Top の **Statement / Philosophy** は**世界観・価値の入口**として**浅く**示し、**思想・原点・行動原理**の**補強と深め**は **`/about`** で主に担う（重なりはあるが、**物語と問題意識の芯**は `/about` に寄せる）。  
- **現在の支援領域・事業・相談**: RAPTOVAが**何をしているか・何を相談できるか** — **`/business`** で主に担う（**表層3事業**での説明・**相談導線**。固定Servicesカタログではない。詳細は **`### /business の役割`**）。  
- **実行・検証・実装**: 何を考え、何を試し、どう形にしたかの**蓄積** — **`/projects`**（一覧・入口）および **`/projects/[slug]`**（個別の深掘り）で主に担う。  

Top はこの流れを**浅くつなぎ**、下層で**それぞれを深める**。**思想**については Top の **Statement / Philosophy** で**世界観・入口**を示し、**原点・行動原理・問題意識の芯**は **`/about`** で主に深める。

### サイト全体の目的

RAPTOVA公式HPは、**営業・信用獲得・事業説明・実績蓄積**のための公式サイトとして設計する。

単なる名刺サイトではなく、次を伝えるための**事業拠点**とする。

- RAPTOVAが**何をしているブランド**なのか  
- **何を相談できる**のか  
- **どの程度の品質で形にできる**のか  
- **誰がどんな思想で運営している**のか  
- **相談・紹介・協業**につながる入口があること  

サイト単体で**即受注**を狙うというより、**営業・紹介・相談の前後で信用を補強すること**を主目的とする。

## レスポンシブ・レイアウト（実装メモ／2026-05-13）

### レイアウト方針（ブレークポイント）

- **〜1439px**: 主要セクションは**縦積み**
- **1440px以上**: **PC向けの左右分割**が有効
- **補足**: 以前は **1280px 付近で「PC分割」相当のレイアウトが誤って出る**ことがあったため、**分割の主因は 1440px 基準**に寄せて整理済み（コード上のブレークポイント定義に従う）

### 小幅端末の最優先

- **横スクロールを出さない**（確認の軸: `document.documentElement.scrollWidth` と `window.innerWidth` が一致すること）

### 横オーバーフロー（原因と対策の考え方）

- **症状（修正前の例）**: 見た目は概ね正常でも横にスワイプでき、右に白余白。Contact で左が切れたように見える／Footer で横ズレ・見切れ
- **原因の捉え方**: 1セクションだけの不具合に閉じず、**ページ全体の横方向オーバーフロー**として扱う
- **対策のレイヤー**:
  - **文書ルート〜ページ骨格（html / body / main）**で、横方向にはみ出さない前提を作る
  - **各主要セクション**と、**grid / flex の子**まで含め、**親より横に膨らまない**ようラッパー階層で幅と横方向クリップを整理
  - 横方向の溢出は **`overflow-x: clip`** を軸に抑える（`hidden` は使わず、**意図を明確にする**）
  - タッチ環境では、**横パンや横方向の余計なスクロール挙動**を抑える指定を追加（細目はコード）
- **背景付きブロックの二層**: **外側はビューポート幅いっぱい**。**最大幅の制限と中央寄せは内側ラッパーだけ**に置く（Hero / Business / Projects / About / Contact / Footer を含む）

### Contact / Footer（スマホ）

- **iPhone 17 相当（402px）**でも、左切れ・右余白・横ズレが出ないよう調整済み
- Contact は、**本文・ボタン**が小幅で収まりやすいよう、字間・余白を詰めすぎない範囲で調整済み（数値の細目はコード参照）

### Next.js（メタ）

- **`viewport` export** を追加し、**`interactiveWidget: 'resizes-visual'`** を明示

- **ブラウザ**: Chromium / WebKit で、**375 / 390 / 393 / 402 / 414 / 853 / 1280 / 1440 / 1600** px を確認。**右方向にはみ出す要素は 0**。Contact / Footer の表示矩形が viewport 内

## ■ RAPTOVAの定義

RAPTOVAは以下のような存在である：

- Web制作会社ではない
- AI導入支援会社でもない
- 採用支援会社でもない

止まっている改善を、
整理・構造化・翻訳・実装によって

「理解可能・実行可能・実装可能な状態へ接続する存在」

---

## ■ 改善停止状態モデル

企業の改善は「不足」ではなく「未接続」によって止まる。

- 認識停止：何が問題か整理できない
- 伝達停止：価値が伝わらない
- 実行停止：動けない
- 実装停止：形にできない

---

## ■ Three Themes（改善翻訳モデル）

改善を前進させる3つの翻訳軸：

- 魅力を、伝わる形にする（価値の翻訳）
- 改善を、動き出す形にする（実行の翻訳）
- 構想を、実装できる形にする（実装の翻訳）

## ■ Projectsの位置づけ

Projectsは制作実績ではなく、

「どの停止状態をどう接続し、どう前進させたか」

を示すケーススタディである。

---

## ■ 全体構造

RAPTOVAの構造は以下で統一される：

認識停止
↓
伝達停止
↓
実行停止
↓
実装停止

これらの停止を
整理 → 翻訳 → 構造化 → 実装 によって接続するのがRAPTOVAである。
